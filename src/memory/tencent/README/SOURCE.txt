Recall utilities
----------------

* `src/recall/budget.ts`
  - Upstream:
      `MemoryCore/src/core/store/search-utils.ts` (RRF_K=60, rrfMerge)
      `MemoryCore/src/core/hooks/auto-recall.ts`
        (applyRecallBudget, normalizeBudgetLimit, truncateRecallLine,
         RECALL_TRUNCATION_SUFFIX="…（已截断；可用 tdai_memory_search 或 tdai_conversation_search 查看详情）",
         MIN_TRUNCATED_RECALL_LINE_CHARS=40,
         RECALL_LINE_SEPARATOR="\n")
  - Modifications:
    - `rrfMerge` is generalized to any `getId` selector (upstream hard-codes

      caller can log/report without re-deriving.
    - `deriveTotalRecallBudget` is a new convenience helper that mirrors
      the upstream "600 chars/memory, derived total" comment.

* `src/recall/memory-tools-guide.ts`
  - Upstream:
      `MemoryCore/src/core/hooks/auto-recall.ts::MEMORY_TOOLS_GUIDE`
  - Modifications:
    - Guide block text is verbatim (Chinese descriptions preserved).
    - Tool names exposed as constants (TOOL_MEMORY_SEARCH,
      TOOL_CONVERSATION_SEARCH, TOOL_READ_FILE) so callers can check the
      budget without string-comparing.
    - `MemoryToolCallBudget` is a new helper that tracks the per-turn
      `≤3 calls` semantic — the upstream logic was inlined in the hook
      body; here it is exposed as a pure class.

Scheduling
----------

* `src/scheduling/pipeline.ts`
  - Upstream:
      `MemoryCore/src/utils/checkpoint.ts`
        (PipelineSessionState, warmup_threshold doubling ladder)
      `MemoryCore/src/core/state/types.ts`
      warmup semantics from `MemoryCore/src/core/store/embedding.ts`
  - Modifications:
    - `advanceWarmup` exposes the doubling ladder (1 → 2 → 4 → 8 → ... →
      everyN) as pure logic. 0 = saturated.

      `memories_since_last_persona`) but the upstream itself uses ad-hoc
      inline checks in different places. The reasoning is brought
      together here.
